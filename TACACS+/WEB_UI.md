# Веб-интерфейс

Учебное приложение в `webui/`. Оно не управляет демоном: устройства и пользователи лежат в sqlite, сессии и журнал читаются из accounting-файла tac_plus-ng. Скрытое поле `csrf_token` есть во всех формах, которые меняют данные (POST). Без него сервер отвечает 400 и просит обновить страницу.

Роли две.

| | admin | user |
| --- | --- | --- |
| Обзор | Счётчики инвентаря, все сессии, хвост журнала | Только свои сессии и свой хвост журнала |
| Устройства | Список, поиск, сортировка, добавление, правка, удаление | Нет пункта меню, URL отвечает 403 |
| Пользователи веб-интерфейса | То же | 403 |
| Сессии | Все открытые | Только строки, где пользователь равен имени входа |
| Журнал | Все строки, фильтр по имени доступен | Только свои строки; `?user=` с чужим именем игнорируется |
| Параметры | Путь журнала, путь базы, флаг Secure | 403 |
| Пароль | Смена своего пароля | Смена своего пароля |
| Выход | Да | Да |

Имя роли `user` должно совпадать с именем в журнале TACACS+, иначе свои сессии не найдутся. Создать такое имя может только admin.

## Вход (`/login`)

Поля: **Имя**, **Пароль**, кнопка **Войти**. Скрытые поля: `csrf_token` и `next` (куда вернуть после входа; принимается только путь, начинающийся с одного `/`).

Неверная пара имя/пароль оставляет на странице текст «Неверное имя или пароль.» Сервер не говорит, чего именно не хватило. Уже вошедшего пользователя страница отправляет на обзор.

`POST /login` ограничен по адресу клиента. По умолчанию 5 запросов в минуту (`LOGIN_RATE_LIMIT` в `.env`). Сверх лимита сервер отвечает кодом 429 и текстом «Слишком много попыток входа. Подождите и попробуйте снова.» Лимит считается до проверки пароля. За nginx адрес берётся из заголовка `X-Real-IP`, который nginx ставит из `$remote_addr`. Без nginx берётся адрес сокета.

После удачного входа браузер получает cookie `tacacs_ui`: флаг HttpOnly, SameSite=Lax, срок 8 часов. Флаг Secure есть, когда в `.env` стоит `SESSION_COOKIE_SECURE=true` (так и должно быть за HTTPS). Старая сессия при входе сбрасывается, скрытое поле `csrf_token` выпускается заново.

## Шапка

После входа на всех страницах: Обзор, Сессии, Журнал, Пароль, кнопка **Выход**. У admin ещё Устройства, Пользователи, Параметры. Справа имя и подпись роли («администратор» или «пользователь»). Выход — POST с `csrf_token`, сессия сбрасывается.

Зелёная плашка — короткое сообщение после сохранения («Устройство добавлено» и похожие).

## Обзор (`/`)

Admin видит число карточек устройств и число веб-пользователей, напоминание, что инвентарь не пишется в `tac_plus-ng.cfg`, число открытых сессий и путь журнала. Ниже до восьми открытых сессий (начало, пользователь, NAS, порт, клиент) и до восьми последних строк учёта (время, тип, пользователь, NAS, команда). Ссылка **Все сессии**.

Пользователь `user` видит ту же раскладку, но строки уже отфильтрованы по его имени. Счётчики инвентаря ему не показываются.

Пустой журнал даёт текст, что открытых сессий нет.

## Устройства (`/devices`)

Только admin.

Поиск — поле и кнопка **Найти**. Ищется подстрока в имени, адресе, группе и типе. **Сбросить** очищает поиск.

Ссылка **Добавить устройство** открывает `/devices/new`.

Таблица: Имя, Адрес, Группа, Тип, Ключ, действия. Заголовок столбца сортирует по нему. Повторный щелчок меняет направление (стрелка ↑ или ↓). Ключ показан администратору целиком: это карточка инвентаря, не экран для посторонних.

**Изменить** открывает `/devices/<id>/edit`. **Удалить** спрашивает подтверждение в браузере и отправляет POST. Удаление убирает строку sqlite и не трогает конфиг демона.

### Форма устройства

Поля: **Имя** (буква, затем буквы, цифры, `.`, `_`, `-`, до 64 символов, уникально), **Адрес или префикс** (IPv4, IPv6 или CIDR), **Ключ TACACS+** (обязателен, до 256 символов), **Группа** (метка до 64 символов, на демон не влияет), **Тип** — список `cisco`, `junos`, `huawei`, `other`.

**Сохранить** пишет строку и возвращает к списку. **Отмена** уходит на список без записи. Ошибки полей выводятся красным под полем, введённые значения остаются.

## Пользователи (`/users`)

Только admin. Это учётные записи браузера, не блок `user` в `tac_plus-ng.cfg`.

Поиск по имени, роли и группе. Столбцы Имя, Роль, Группа сортируются так же, как у устройств. **Добавить пользователя** ведёт на `/users/new`. **Изменить** — на `/users/<id>/edit`. **Удалить** есть у всех, кроме своей строки: себя удалить нельзя, последнего admin тоже. Подтверждение — диалог браузера.

### Форма пользователя

**Имя** — те же правила, что у устройства. **Пароль** — не короче 8 символов; при правке пустое поле не меняет пароль. В базе остаётся хеш argon2id. **Роль**: `admin` (полный доступ) или `user` (только свои сессии и журнал). Снять admin с самого себя форма не даст. **Группа** — свободная метка.

## Сессии (`/sessions`)

Страница сама обновляется каждые 10 секунд (`meta refresh`).

Колонки: Начало, Пользователь, NAS, Порт, Клиент, task_id, priv, Сервис. Открытая сессия — запись `start`, после которой нет `stop` самой сессии с тем же NAS, именем и `task_id`. `stop` с текстом команды (`cmd` / `cmd-arg`) — это учёт команды, сессию он не закрывает. Закрывает `stop` без команды. Если `task_id` пустой, пара ищется по порту.

Над таблицей указан путь журнала. У роли `user` добавлено, что чужое имя в адресе не учитывается. Кнопки разрыва сессии нет.

## Журнал (`/accounting`)

Фильтр (GET, страницу не меняет на сервере помимо выборки):

- **Пользователь** — только у admin, точное совпадение имени. У `user` поля нет.
- **NAS** — подстрока адреса.
- **Текст команды** — подстрока команды или сервиса.
- **С** и **По** — время `ГГГГ-ММ-ДД` или `ГГГГ-ММ-ДД ЧЧ:ММ:СС`.

**Фильтр** применяет условия. **Сбросить** открывает журнал без них.

Таблица: Время, Тип (`start` / `stop` / `update`), Пользователь, NAS, Порт, Клиент, Команда, task_id. По 50 строк. Ссылки **Назад** и **Дальше** и подпись «Страница N из M» сохраняют фильтр.

## Параметры (`/settings`)

Только admin. Таблица только для чтения: путь accounting, URL sqlite, флаги cookie (HttpOnly — всегда да, SameSite — `lax`, Secure — как в `SESSION_COOKIE_SECURE`), срок cookie (8 часов), лимит входа (`LOGIN_RATE_LIMIT`), интервал обновления сессий (10 секунд). Секрет `APP_SECRET_KEY` и пароль администратора не выводятся. Текст внизу объясняет, что bootstrap-переменные действуют один раз.

## Пароль (`/account/password`)

Обе роли. Поля: **Текущий пароль**, **Новый пароль**, **Новый пароль ещё раз**, кнопка **Сохранить**. Новый пароль не короче 8 символов и должен совпасть с повтором. Неверный текущий пароль, короткий новый или несовпадение повтора оставляют на странице красный текст. Успех возвращает на обзор с плашкой «Пароль изменён.» Меняется только веб-пароль.

## Отказ

Чужой раздел для роли `user` — страница «Нет доступа» с кодом 403. Несуществующий id устройства или пользователя — «не найден» с кодом 404. Устаревшая форма — 400. Слишком частый вход — 429.
