# TACACS+ для AAA на сетевом оборудовании

Учебный контур: устройства (NAS) спрашивают центральный сервер **tac_plus-ng** (Event-Driven Servers, Marc Huber, pro-bono-publico), можно ли пустить пользователя, какую роль ему дать и что записать в журнал. Пример сервера — [`server/tac_plus-ng.cfg`](server/tac_plus-ng.cfg). Короткий эквивалент на классическом **tac_plus** (Shrubbery) — [`server/tac_plus.conf`](server/tac_plus.conf).

Адреса `192.0.2.0/24` и пароли в примерах взяты из диапазона документации (RFC 5737). Перед боевым включением их заменяют.

## Как устроен TACACS+

Протокол разделяет три независимых запроса. Это и есть AAA:

| Часть | Вопрос к серверу | Когда |
| --- | --- | --- |
| Authentication | Кто это и верный ли пароль? | Логин, иногда отдельный enable |
| Authorization | Что этому пользователю можно? | Старт exec-сессии и (если настроено) каждая команда |
| Accounting | Что уже произошло? | Старт/стоп сессии и выполненные команды |

Запрос авторизации не «спрятан» внутри ответа аутентификации. NAS может спросить пароль у одного сервера, а разрешение на команду — у другого. Поэтому на Huawei в шаблоне HWTACACS три отдельные строки: authentication, authorization, accounting.

Транспорт — **TCP/49**. Сессия ориентирована на соединение: запрос и ответ связаны sequence number, сервер видит обрыв TCP. Флаг single-connection позволяет не открывать новый TCP на каждый AAA-запрос; его включают на NAS, сервер tac_plus-ng его принимает.

Общий ключ (shared secret) задаётся парой NAS и сервер. По RFC 8907 тело пакета обфусцируется гаммой на MD5 (session id, ключ, версия, номер последовательности и предыдущий блок гаммы). В теле лежат имя, пароль, аргументы команды и атрибуты авторизации. Заголовок (12 байт: version, type, seq_no, flags, session_id, length) остаётся открытым, поэтому «шифруется весь пакет» — бытовая формулировка: шифруется весь полезный груз AAA, а не только пароль. Это не TLS. Ключ в пути не передаётся; несовпадение ключа выглядит как битый пакет, а не как «неверный пароль».

## Сравнение с RADIUS

| | TACACS+ | RADIUS |
| --- | --- | --- |
| Транспорт | TCP/49 | UDP/1812 (auth), UDP/1813 (acct) |
| Секрет | Обфусцирует тело пакета целиком | Прячет в основном User-Password; остальной Access-Request читается |
| Авторизация | Отдельный запрос, можно резать команды по одной | Атрибуты приезжают сразу в Access-Accept, на логине |
| Учёт команд | Отдельная запись на команду | Обычно только старт/стоп сессии |
| Типичное место | Админский вход на оборудование | Доступ абонентов (PPP, 802.1X, VPN) и платформы без клиента TACACS+ |

MikroTik RouterOS как раз из второго столбца: своего клиента TACACS+ у него нет, для входа администратора используется RADIUS. См. [`devices/mikrotik-routeros.md`](devices/mikrotik-routeros.md).

## Типовая схема

```
админ (SSH/NETCONF)
        |
        v
   NAS (коммутатор, маршрутизатор)
        |  TCP/49, ключ этого NAS
        +----> tac_plus-ng primary   192.0.2.10
        |
        +----> tac_plus-ng secondary 192.0.2.11   (если primary не ответил)
        |
        +----> локальная учётная запись         (только если серверы недоступны)
```

NAS — клиент TACACS+. Сервер хранит пользователей, группы и правила. На сервере объект называется `device`: это адрес, с которого придёт пакет, и ключ именно этого устройства.

Резервирование — второй сервер с той же базой пользователей (или репликой файла). Устройство перебирает серверы по таймауту, а не по отказу в пароле. Отказ («пароль неверен» / FAIL) — окончательный. Локальный пароль нужен на случай тишины: сервер выключен, сеть до него мертва, TCP/49 фильтруется. Иначе при аварии AAA на устройство не зайти.

Практический минимум:

1. Локальный аварийный пользователь создаётся **до** переключения аутентификации на TACACS+.
2. У каждого NAS свой ключ. Общий ключ на всю сеть удобен и опасен: утечка с одного устройства компрометирует разбор пакетов остальных.
3. Адрес источника на NAS фиксируют (loopback, `source-interface` / `source-address` / `source-ip`). Иначе сервер увидит адрес исходящего интерфейса и не попадёт в нужный `device`.
4. Авторизация команд без рабочего сервера легко запирает CLI. Метод `local` / `if-authenticated` на NAS — запасной выход при недоступности, не вторая попытка после явного deny.

Проверка синтаксиса основного файла (демон должен быть установлен):

```bash
tac_plus-ng -P TACACS+/server/tac_plus-ng.cfg
```

`-P` только разбирает файл и завершается. Демон с ошибкой в конфигурации не стартует.
