```text

Стиль: тёмный фон (почти чёрный), моноширинный шрифт, зелёный текст как в терминале, эффект набора текста. Без логотипов, без музыки на фоне голоса, без воды — только суть.

Тема: Урок 21. ACL.

Сюжет по сценам:
0–5 с — хук: Фильтр трафика в одной строке. Но порядок решает всё.
5–20 с — Логика: правила сверху вниз, первое совпадение — конец проверки, в конце скрытый deny any
20–40 с — Cisco extended named ACL: `ip access-list extended WEB-ONLY` · `permit tcp 192.168.1.0 0.0.0.255 any eq 443` · `permit udp 192.168.1.0 0.0.0.255 any eq 53` · `deny ip any any log` · `interface Gi0/0` `ip access-group WEB-ONLY in`
40–55 с — Wildcard-маска: 0.0.0.255 = инверсия /24 · standard ACL ставим ближе к получателю, extended — ближе к источнику · `show access-lists` (счётчики совпадений)
55–60 с — финальная строка крупно по центру: «Сверху вниз, первое совпадение, в конце implicit deny.»

Закадровый голос (спокойный, уверенный, по-русски):
ACL — это как охранник со списком на входе: он читает список сверху вниз и пропускает или не пускает по первой подходящей строке. Если никакая строка не подошла, работает невидимое правило в конце — запретить всё. Поэтому порядок строк важнее их количества. Стандартный ACL смотрит только на адрес источника, расширенный — на протокол, адреса и порты. Вместо обычной маски используется wildcard — инверсия, ноль значит «проверять бит». Расширенные списки вешают ближе к источнику, чтобы лишний трафик не ехал через всю сеть. Счётчики совпадений в show access-lists покажут, какое правило реально срабатывает.

Финальная строка-вывод: Сверху вниз, первое совпадение, в конце implicit deny.
```
