# Урок 39. DMVPN

```text
Стиль: тёмный фон (почти чёрный), моноширинный шрифт, зелёный текст как в терминале, эффект набора текста. Без логотипов, без музыки на фоне голоса, без воды — только суть.

Тема: Урок 39. DMVPN.

Сюжет по сценам:
0–5 с — хук: Сто филиалов, и каждый может говорить с каждым без ста туннелей.
5–20 с — Компоненты: mGRE (один туннельный интерфейс) · NHRP (кто за каким публичным адресом) · IPsec (шифрование) · фазы 1/2/3
20–40 с — Hub: `interface Tunnel0` · `ip address 10.255.0.1 255.255.255.0` · `ip nhrp network-id 1` · `ip nhrp map multicast dynamic` · `ip nhrp redirect` · `tunnel source Gi0/1` · `tunnel mode gre multipoint` · `tunnel protection ipsec profile DMVPN`
40–55 с — Spoke: `ip nhrp nhs 10.255.0.1 nbma 203.0.113.1 multicast` · `ip nhrp shortcut` · `show dmvpn` → туннель spoke-spoke поднимается по требованию
55–60 с — финальная строка крупно по центру: «mGRE + NHRP + IPsec = динамические туннели spoke-to-spoke.»

Закадровый голос (спокойный, уверенный, по-русски):
DMVPN — это как корпоративная телефонная станция: каждый филиал сначала звонит в центр, а центр подсказывает прямой номер другого филиала, и дальше они говорят напрямую. Все туннели живут на одном интерфейсе multipoint GRE. Протокол NHRP — справочник, который знает, какой внутренний адрес за каким публичным. Сверху IPsec шифрует трафик. Во второй и третьей фазе филиалы строят прямые туннели друг к другу по требованию, а в третьей это делается через redirect и shortcut. Поверх работает обычная маршрутизация — EIGRP, OSPF или BGP.

Финальная строка-вывод: mGRE + NHRP + IPsec = динамические туннели spoke-to-spoke.
```
