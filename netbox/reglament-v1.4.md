# РЕГЛАМЕНТ РАБОТЫ С СЕРВИСОМ NetBox

*Сетевой отдел · Внутренний документ · Версия 1.4*

## 1. Назначение

NetBox является единым источником истины (source of truth) сетевой инфраструктуры компании. Все данные о VLAN, подсетях, префиксах и сетевом оборудовании вносятся исключительно через NetBox. Конфигурации сетевых устройств строятся на основе данных NetBox. Любые изменения в инфраструктуре сначала фиксируются в NetBox, затем применяются на оборудовании.

## 2. VLAN-группы

VLAN-группы используются для логического разделения VLAN по площадкам и по оборудованию, на котором терминируются сети. Каждая VLAN-группа привязывается к одной площадке или к одному такому устройству: это закрепляет область видимости VLAN и гарантирует уникальность ID внутри группы.

- Создать VLAN-группу: меню IPAM → VLANs → VLAN Groups → кнопка + Add.
- Поле Name — название группы, отражающее отдел и площадку или оборудование, например: `vlan-group-sales-msk`, `vlan-group-it-spb`, `vlan-group-agg01`.
- Поле Slug — URL-идентификатор, формируется автоматически из имени (латиница, строчные буквы, дефисы).
- Поле Scope — привязка группы к объекту: регион, группа сайтов, сайт, локация, группа стоек, стойка, группа кластеров или кластер. Выбирается та площадка или то оборудование, к которому относится группа.
- Поле VLAN ID Ranges — список допустимых диапазонов VID внутри группы (например `100-199,300-399`; диапазоны не должны пересекаться). По умолчанию 1–4094. При необходимости сужается под нужды отдела.
- Внутри одной группы каждый VLAN ID и имя уникальны. VLAN из разных групп могут иметь совпадающие ID — это нормально и не является ошибкой.

**Правило: одна VLAN-группа — это одна площадка или одно оборудование, на котором терминируются сети (например, ядро или агрегация). Отдел может иметь несколько VLAN-групп — по числу площадок. Не создавать «общую» группу для всей компании.**

### Примеры применения

1. Отдел с двумя площадками. Отдел продаж работает в Москве и Санкт-Петербурге — создаются две группы: `vlan-group-sales-msk` и `vlan-group-sales-spb`. Scope каждой группы — свой сайт. VLAN с одинаковыми ID на разных площадках конфликта не вызывают.
2. Оборудование-агрегатор для нескольких отделов. На одном физическом коммутаторе агрегации терминируются сети нескольких отделов — для этого устройства создаётся одна группа, например `vlan-group-agg01`. Все VLAN, терминируемые на нём, вносятся в эту группу, и уникальность VID проверяется ровно там, где она нужна.
3. Площадка без чёткой принадлежности отделу. Для площадки, которая не закреплена за конкретным отделом (склад, удалённый офис, серверная), группа называется по имени площадки, например `vlan-group-ekb-warehouse`.

## 3. VLAN

VLAN создаётся в меню IPAM → VLANs → VLANs → кнопка + Add (или через вкладку Bulk Create формы создания для массового ввода ID и диапазонов, например: `100,200-210`, с плейсхолдером `{vid}` в имени, например `VLAN-{vid}`).

- Обязательные поля: ID (VID 1–4094), Name (имя как на конфигурации коммутатора), Status.
- Поле VLAN Group — группа, к которой относится VLAN. Назначается всегда. Прямая привязка VLAN к сайту в NetBox объявлена устаревшей (deprecated) и регламентом не используется.
- Поле Role — функциональная роль VLAN (Data, Voice, Management и т. п.), если применимо.
- Поле Tenant — арендатор, при необходимости.

## 4. Префиксы (подсети)

Префикс создаётся в меню IPAM → Prefixes → Prefixes → кнопка + Add. К одному префиксу может быть привязан VLAN из любой группы — ограничений по группам нет. Это позволяет, например, привязать к префиксу отдела продаж VLAN из группы мониторинга.

- Поле Prefix — сеть в CIDR-нотации, например `10.40.10.0/24`.
- Поле Status — операционный статус: Active, Reserved, Deprecated и др.
- Поле VRF — экземпляр VRF, если префикс находится в нём.
- Поле Role — функциональная роль префикса (согласуется с ролью привязанного VLAN).
- Поле VLAN — VLAN, которому принадлежит префикс. Выбирается из списка с учётом группы.
- Поле Scope — регион, группа сайтов, сайт или локация (с NetBox 4.2 заменило поле Site).
- Поле Is a pool — все адреса префикса (включая сетевой и широковещательный) считаются пригодными для назначения.
- Поле Mark utilized — принудительная отметка 100% утилизации.

## 5. Теги

Теги создаются администратором в меню Customization → Tags → кнопка + Add (поля: Name, Slug, Color, Description, Weight, Object Types). После создания тег назначается объектам через поле Tags в формах создания и редактирования.

- Префиксам назначаются теги, отражающие их назначение или зону ответственности.
- Оборудованию назначаются теги по сетям, за которые оно отвечает. Пример: оборудование мониторинга помечается тегом mon.
- Имена тегов — короткие, латиницей, строчными буквами: mon, core, dist, access.

## 6. Description и комментарии префиксов

Каждый префикс обязан иметь заполненное поле Description с кратким назначением подсети. Номер тикета на изменение или выделение подсети указывается в поле Comments в формате: `Ticket: NET-1234`. Без номера тикета префикс считается незадокументированным и подлежит исправлению.

## 7. Роли оборудования

Роли устройств создаются в меню Devices → Device Roles → кнопка + Add (модель DCIM). Каждому устройству назначается ровно одна роль (роль задаётся у устройства, а не у типа оборудования). Базовый набор ролей:

- core — ядро сети (core switches);
- dist — дистрибуционный уровень (distribution switches);
- access — уровень доступа (access switches).

Роль назначается в поле Role при создании устройства (Devices → Devices → + Add, подробно — в разделе 8). Дополнительно устройству задаются теги по сетям, за которые оно отвечает.

## 8. Добавление оборудования

Устройство создаётся в меню Devices → Devices → кнопка + Add. Порядок действий:

1. Заполнить обязательные поля: Name, Device role (core / dist / access), Device type, Site, Status (обычно Active).
2. Привязать к месту установки: Location, Rack, Rack face (Front/Rear) и Position (нижний занимаемый юнит). При необходимости — Tenant, Platform, Tags (зоны ответственности).
3. Заполнить Description и указать номер тикета в Comments (`Ticket: NET-1234`) — так же, как для префиксов.
4. Интерфейсы: создаются автоматически из шаблонов Device type или добавляются вручную на вкладке Interfaces устройства (+ Add Components → Interfaces).
5. IP-адрес берётся из выделенного префикса: IPAM → IP Addresses → IP Addresses → + Add, либо на странице префикса вкладка IP Addresses / кнопка Add an IP Address (свободные адреса показываются в списке).
6. В форме IP-адреса на вкладке Interface assignment выбрать Device и Interface. Можно сразу отметить «Make this the primary IP for the device/VM».
7. Либо отредактировать устройство и выбрать Primary IPv4 / Primary IPv6. Выбрать можно только адрес, уже назначенный интерфейсу этого устройства.

### Пример

| Поле | Значение |
|---|---|
| Name | `agg01.sales.msk` |
| Device role | core |
| Device type | Cisco Catalyst 9300 (пример) — см. «Типы устройств» |
| Site / Rack / Position / Face | msk / msk-r01 / U40 / Front |
| Status | Active |
| Tags | sales, core |
| Interface | Vlan10 (тип Virtual) |
| Prefix (IPAM) | `10.10.0.0/24` |
| IP Address | `10.10.0.1/24` → интерфейс Vlan10 устройства `agg01.sales.msk` |
| Primary IPv4 | `10.10.0.1/24` |
| Description / Comments | Агрегация отдела продаж, Москва / `Ticket: NET-1234` |

### Типы устройств (Device Types)

Device type — шаблон модели оборудования: производитель, модель, высота и глубина, а также шаблоны компонентов (interface templates, console port / power port templates и др.). При создании устройства этого типа NetBox автоматически создаёт на нём реальные компоненты (интерфейсы, порты) по шаблонам. Изменения типа позже не применяются к уже созданным устройствам задним числом.

- Сначала создаётся производитель: Devices → Manufacturers → + Add.
- Затем тип: Devices → Device Types → + Add. Поля: Manufacturer (manufacturer), Model (model), Slug (slug), Height (U) (u_height; 0 — не монтируется в стойку), Is full depth (is_full_depth), Airflow (airflow, например Front to rear). При необходимости: Part number, Default platform, Exclude from utilization, Weight.
- Шаблоны интерфейсов: на странице типа кнопка + Add Components → Interfaces. Поля: Name, Type, Management only, Description. Тип выбирается из списка NetBox, например SFP+ (10GE), QSFP+ (40GE).
- Шаблоны создаются пачкой по шаблону имени с диапазоном в квадратных скобках: `TenGigabitEthernet1/0/[1-24]` создаёт 24 шаблона.
- Готовые типы можно загрузить через Devices → Device Types → Import (YAML), взяв описание из библиотеки сообщества: `github.com/netbox-community/devicetype-library`.

### Пример типа устройства (условная конфигурация)

Набор портов взят для иллюстрации: у реальных моделей Catalyst 9300 он другой (40G-аплинки ставятся сетевыми модулями). Для боевого типа берите модель из devicetype-library.

| Поле | Значение |
|---|---|
| Manufacturer | Cisco |
| Model / Slug | Catalyst 9300 (пример) / `cisco-catalyst-9300-example` |
| Height (U) / Is full depth | 1 / да |
| Airflow | Front to rear |
| Interface templates | `TenGigabitEthernet1/0/[1-24]` — SFP+ (10GE), 24 шт. |
|  | `FortyGigabitEthernet1/1/[1-4]` — QSFP+ (40GE), 4 аплинка |

При создании `agg01.sales.msk` с этим типом на устройстве сразу появятся 28 физических интерфейсов; виртуальный Vlan10 добавляется вручную.

## 9. Обязательные правила

1. Никаких изменений на оборудовании без предварительной записи в NetBox.
2. VLAN без группы не создаются.
3. Префикс без description и номера тикета в comments не принимается.
4. У каждого устройства — ровно одна роль и теги зон ответственности.
5. Теги и роли не удаляются при наличии привязанных объектов.
