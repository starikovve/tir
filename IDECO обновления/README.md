# Ideco NGFW Novum: миграция 22.7.14 → 23.4.40

**Текущая версия:** 22.7.14 (05.08.2026)
**Целевая версия:** 23.4.40 (23.10.2026) — релиз безопасности
**Документация:** https://docs.ideco.ru/v23/ru/ngfw/changelog/ngfw/23-4

---

## 1. Что поменяется

### 1.1. Безопасность (23.4.40)
- Закрыты критические RCE-уязвимости PHP (CVE-2026-109618, CVE-2026-109619) в Web-почте
- Уязвимости Roundcube: XSS, CSRF, IMAP-инъекции
- Три DoS-уязвимости высокой степени до входа по IMAP
- WAF по умолчанию защищает от этих же CVE PHP-приложения, опубликованные через «Обратный прокси»
- Утилита `ideco-vce` и общий каталог `/tmp/cross-dir` для работы с VCE

### 1.2. Мажорный релиз 23.0 (28.08.2026) — перенос с 22.x
- **Контроль ИИ-приложений:** 83 новых протокола (ChatGPT, Claude, DeepSeek, GigaChat, YandexGPT, прокси вроде Chad AI, GPTunneL). Распознавание по DNS, SNI, характеристикам соединений без обязательного TLS-декрипта
- **Категории контент-фильтра:** «ИИ-агенты», «ИИ-сервисы»
- **Отчёты:** вкладка «ИИ-трафик» (топ веб-трафика, топ заблокированного, топ протоколов)
- **Динамическая маршрутизация:** Prefix list, Route map, BFD-профили, зоны OSPF, агрегация BGP, цепочки ключей (md5, hmac-sha-256/384/512)
- **QoS:** классификация и приоритизация трафика, метки DSCP, ограничение полосы для второстепенных приложений — только в высокопроизводительном контексте
- **Защита от туннелирования:** блокировка туннелированного трафика внутри SSH и TLS/SSL (опция «Запретить туннелированный трафик» в профиле инспекции)
- **Аутентификация Ideco Client по сертификату** на аппаратном токене или смарт-карте вместо пароля; проверка CRL в активной сессии с отзывом доступа на лету
- **Объекты-домены с маской** (*.domain.com) — одно правило на группу поддоменов
- **MTU и MSS** для интерфейсов и IPsec (MSS отдельно для IPsec против фрагментации в туннелях)
- **ГОСТ:** алгоритмы ГОСТ для публикации ресурсов по ГОСТ TLS, сертификаты ГОСТ, ГОСТ в обратном прокси
- **Виртуальный коммутатор между VCE:** veth-пара и виртуальный L2-интерфейс для трафика между контекстами без внешнего оборудования; BGP и LACP между VCE
- LDAP/LDAPS с валидацией сертификата DC; RADIUS с NAS-Identifier/NAS-IP-Address/NAS-Port; API отдаёт дату последней смены пароля локальных учёток; веб-аутентификация ограничена выбранными подсетями в ВП-контексте

### 1.3. Поведение при обновлении
- Настройки, правила и данные **мигрируют автоматически**
- Автообновление на следующую мажорную версию возможно **только с последней минорной** текущей ветки; ручное — с любой
- Обновления можно отложить до 6 месяцев или навсегда
- 23.4.40 — патч внутри 23.x, минорный, автообновление штатное

## 2. Что проверить ПЕРЕД обновлением

### 2.1. Инвентаризация
- [ ] Список VCE-контекстов и способ доступа к каждому (SSH / веб / Center)
- [ ] Скрипты и автоматизации, которые подключаются к VCE напрямую (по SSH или по URL веб-интерфейса VCE)
- [ ] Наличие встроенного почтового сервера (Roundcube) и активных ящиков
- [ ] PHP-приложения за обратным прокси (WAF)
- [ ] Версия Ideco Center (нужна 23.4.54 или новее для синхронной работы)
- [ ] Протоколы VPN: IKEv2/IPsec, SSTP, SSL — убедиться, что PPTP нигде не остался (умер в 22.0)
- [ ] BGP/OSPF-соседи и текущие политики маршрутизации
- [ ] Тип контекста: классический или высокопроизводительный (VPP) — от этого зависит QoS
- [ ] Ideco Client: профили пользователей, способ аутентификации
- [ ] Сертификаты и PKI: есть ли инфраструктура выпуска/отзыва (CRL), токены
- [ ] Резервная копия конфигурации (полный дамп / снимок VM)

### 2.2. Совместимость окружения
- [ ] Достаточно места на диске под обновление (проверить в Управление сервером → состояние)
- [ ] Нет запланированных работ на окно обновления
- [ ] AD/ALD/RADIUS-интеграции отвечают, LDAP-пути корректны
- [ ] Redbox API и Oxidized: эндпоинты NGFW не захардкожены под старый URL/порт
- [ ] Juniper: BGP-сессии к NGFW, prefix-list на стороне Juniper — после смены политик на NGFW может понадобиться согласование

## 3. Что нужно ИЗМЕНИТЬ перед обновлением

### 3.1. VCE-доступ (критично для 23.4.40)
- [ ] Переписать скрипты/автоматизации с прямого SSH/веб-доступа к VCE на работу через системный контекст или `ideco-vce` + `/tmp/cross-dir`
- [ ] Проверить, что Center 23.4.54+ развёрнут и NGFW к нему подключён
- [ ] Убедиться, что администраторы знают новый путь входа в VCE

### 3.2. Маршрутизация (если есть BGP/OSPF)
- [ ] Зафиксировать текущие neighbor-конфиги и политики (prefix-list/route-map на Juniper и NGFW)
- [ ] Решить, какие prefix-list и route-map переносить в 23.x — они не мигрируют как политики, только как данные
- [ ] BFD-профили создавать заново

### 3.3. QoS
- [ ] Если нужен QoS — убедиться, что трафик идёт через ВП-контекст; в классическом он недоступен
- [ ] Спроектировать DSCP-метки и правила классификации до обновления

### 3.4. Аутентификация Ideco Client
- [ ] Если планируется вход по токену: выпустить/разместить сертификаты, настроить CRL, проверить отзыв в тестовой сессии
- [ ] Парольная аутентификация остаётся, но модель риска меняется

### 3.5. Контент-фильтр и ИИ
- [ ] Включить модуль «Контроль приложений» после обновления
- [ ] Просмотреть всплывшие ИИ-протоколы и решить политику: разрешить/запретить/мониторить
- [ ] Категории «ИИ-агенты»/«ИИ-сервисы» — привязать к правилам

### 3.6. WAF / обратный прокси
- [ ] Инвентаризация PHP-приложений за reverse proxy
- [ ] Подготовить белый список / исключения для легитимного трафика

### 3.7. Почта
- [ ] Тестовый ящик: вход, отправка, получение — прогнать после обновления
- [ ] Проверить, что IMAP/SMTP-порты и клиенты не завязаны на старое поведение Roundcube

### 3.8. MTU/MSS
- [ ] Для IPsec-туннелей выставить MSS отдельно, чтобы избежать фрагментации

## 4. Порядок обновления (рекомендуемый)

1. Резервная копия конфигурации и снимок VM
2. Обновить Ideco Center до 23.4.54 (если есть)
3. Поставить NGFW в режим обслуживания / выбрать окно
4. Ручное обновление 22.7.14 → 23.4.40 (с любой минорной можно)
5. Дождаться автомиграции настроек
6. Проверки после: VCE-доступ, почта, WAF, BGP-соседи, Ideco Client, QoS-контекст
7. Включить контроль приложений, посмотреть ИИ-трафик
8. Задокументировать изменения, обновить Oxidized/Redbox-конфиги при необходимости

---

## 5. Откат

- Автообновление: при проблемах можно отложить на срок, но откат мажорной версии после автомиграции — через восстановление из резервной копии
- Ручное обновление: иметь под рукой образ/дамп 22.7.14
